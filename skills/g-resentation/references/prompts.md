# Prompt 库

原文（《今天，公开一套我用AI做PPT的方法论》，超级硬核的Daniel）的七条提示词，按本流程的顺序重排。

**用之前必须做的两件事：**

1. 所有 `［ ］` 和 `【 】` 用 `brief.md` 里的真实内容替换，一个都不许留。留了就是没问清。
2. 每条 prompt 前先说明用哪条路、读哪几个文件，别把孤立的 prompt 直接丢给模型。

**和原文不同的两处（故意的）：**

- 原文 ③④ 是"直接完成整套，中途别等我"。本流程改为先出三页样稿再放量，样稿要求已写进对应 prompt 里。
- 原文 ⑥ 自带三页样稿，本来就是对的，原样保留。

## P1 · 整理逐页稿 —— 第 3 步

产出直接写进 `outline.md`，编号 P01 起。写完跑 `check_outline.py`。

```
请阅读我上传的内容说明、原始资料和图片素材（或者访问该项目的本地文件目录）。本轮只整理内容，不生成PPT、不生图。
先用几句话复述你理解的：这份PPT给谁看、用于什么场合、核心观点是什么，以及希望观众看完记住什么。

请区分几类材料的用途：
- 原始资料：用于提取信息、核对事实。
- 正式素材：用于后续页面展示。

如果缺少会影响核心观点、内容取舍或事实准确性的信息，先集中列出需要我补充的问题。其他不影响主线的缺项，可以标注"待补充"，继续整理。
然后按照我提供的页数、顺序和逐页要求，整理成逐页稿。如果我没有指定分页，请结合演讲时长建议页数和顺序，并简要说明安排逻辑。

每页写清楚：
1. 标题：优先表达这一页的核心观点
2. 想表达的意思：这一页要让观众理解什么
3. 屏幕文字：实际放在页面上的精简文案
4. 数据与来源：注明对应文件、页码或链接；没有则不填
5. 图片素材：写出要使用的文件名及用途；缺少则标注待补充
6. 建议布局：简要说明文字、图片或图表如何组织
7. 演讲备注：放不必全部显示在屏幕上的补充说明

允许精简表达，但不能改变原意，不得补造数字或事实。
必须保留我明确指定的内容；如建议调整，请单独说明。
资料有冲突、内容有重复、某页太挤，请具体指出并给出建议。
不要为了凑页数添加空泛章节，也不要把所有资料都塞进PPT。

最后汇总需要我确认或补充的事项。等我确认逐页稿后，再进入设计。
```

产出落到 `outline.md` 后，把编号统一成 `P01`、`P02`，标题写在编号那一行。

## P2 · 拆解风格参考 —— 第 5 步，可选

只在有参考图、或用户对视觉要求高时用。没有参考图就跳过，风格由制作环节的默认走。

```
请结合已经确认的逐页稿，分析我提供的风格参考。
本轮先确定设计方向，不生成PPT、不生图。

我喜欢：【具体特点，例如米白底色、大标题、图片排布】
我不喜欢：【具体特点，例如装饰过多、正文太小】
使用场景：【现场投屏/电脑阅读/打印】
其他限制：【品牌色、中文字体、页面比例等；没有可留空】

先简要拆解参考图中的：配色、字体特征、字号层级、对齐方式、留白、图片处理和装饰元素。
请区分哪些是图片中能明确观察到的，哪些是你根据我的内容提出的设计建议。无法确认的字体，不要猜成确定的字体名称，可以推荐气质接近、支持中文的替代字体。
然后提出几个构图明显不同的设计方向，不要只是更换颜色。

每个方向说明：
1. 整体视觉特点，以及为什么适合这份内容
2. 背景色、正文色、强调色，给出建议色值
3. 中文字体、标题和正文字号、页面边距
4. 封面、普通图文页、数据页、流程页的布局建议；只覆盖逐页稿中实际需要的页面类型

保持整体风格一致，但不要让每页长得一模一样。参考图中的小字、低对比度或过密排版，如果不适合我的使用场景，请指出并调整。不要为了套用参考风格，擅自删改已经确认的核心内容。
等我选定方向后，再整理成"风格说明.md"。如果当前环境不能保存文件，就输出可直接复制的Markdown。
后续制作沿用这份说明。
```

## P3 · HTML Slides —— 第 5 步，网页路线

配合 `frontend-slides` 或 `guizang-ppt-skill`。开头一段是追加的样稿检查点。

```
请使用［选定Skill］，根据已确认的逐页稿、风格说明和正式素材，制作HTML Slides。

先做三页样稿：封面、信息最多的一页、图表或流程最复杂的一页，导出可本地打开、能真实翻页和缩放的版本。我确认方向后再出全套。

用于［演示场合］，面向［目标受众］。
保持原有内容逻辑与页序，页面编号与逐页稿一致（P01 就是第一页），不新增未经资料支持的事实、数字或结论。

一、页面与视觉
采用固定16:9画布，在不同窗口尺寸下整体等比缩放，不能拉伸、裁切正文，或让页面内容溢出。不要做成需要上下滚动阅读的长网页。
标题和正文使用真实HTML文字，图表、流程和示意图尽量使用可渲染的元素，不要把整页图片当作HTML幻灯片。
沿用已确认的风格，统一配色、字体层级和页脚。根据内容调整构图，避免每页套同一种卡片布局。

二、演示与交互
支持左右键翻页、上一页和下一页按钮、全屏及页码。提供目录或概览，方便现场跳转到指定页面。
动画只用于解释顺序、状态变化和突出重点。需要交互的页面，可以使用分步展开、方案切换等方式，但不能让关键内容只能通过悬停才能看到。操作后应能返回初始状态，方便重复演示。

三、离线与备用材料
优先交付可本地打开、断网使用的版本，将必要的图片、字体和脚本一并打包，不依赖外部CDN或临时图片链接。
如果必须启动本地服务，或某项功能需要联网，请提前说明，并给出明确的打开方式。
同时导出PDF备用稿，一张幻灯片对应一页。PDF中展示动画和交互页面的完整关键信息，不要出现空白、隐藏内容或演示控制按钮。

四、检查与交付
在浏览器中检查全部页面的文字、图片和交互，测试翻页、全屏、窗口缩放、页面跳转和断网重开。修正文字溢出、元素遮挡、图片丢失等问题。
交付入口HTML、完整素材文件夹和PDF备用稿，整理到同一文件夹中，并告诉我从哪个文件打开、需要什么运行条件，以及还有哪些已知限制。
```

## P4 · 生成整页图 —— 第 5 步，出图路线

```
请根据我上传的原始资料、正式素材、已确认的逐页稿和风格参考，生成一套16:9宽屏比例的幻灯片图片，用于［汇报场合］，面向［目标受众］。
使用GPT Image 2.5生成图片。如果当前入口无法选择或确认该模型，请如实说明，不要仅凭提示词声称已切换模型。

先只生成三页样张：封面、信息最多的一页、图表或流程最复杂的一页。我确认风格后，再按逐页稿一次性完成其余页面。

一、内容依据
以已确认的逐页稿为内容依据，原始资料用于核对事实，正式素材用于页面展示，参考图片只用于借鉴视觉风格。
准确保留核心观点、数据、单位、时间和来源。允许为适应屏幕阅读精简措辞，但不能改变原意，不能自行补充事实、案例、数字或结论。发现资料冲突或关键信息缺失时，先指出，不要猜测。

二、视觉风格
提炼参考图中的配色、字体气质、标题层级、留白、对齐方式和图片处理方式，并贯穿整套页面。
根据每页内容选择合适的构图：封面突出主题，观点页突出结论，数据页突出比较，流程页突出步骤与关系。保持整体统一，同时让不同页面有各自的信息重点，不要每页套用同一个版式，也不要只换背景颜色。

三、信息表达
每页围绕一个明确主题组织信息，建立清楚的阅读顺序。避免大段文字堆砌，将补充说明留在逐页稿中，画面优先呈现观众需要看清、记住的内容。
根据内容需要使用图片、图表、流程图或机制示意图，不要为了装饰强行增加图形：
1. 数据比较：选择适合的图表，保留数值、单位和统计口径
2. 步骤说明：展示先后顺序、关键节点和必要分支
3. 机制解释：明确组成部分及其关系，不编造因果
4. 重点总结：提炼已有结论，不新增空泛口号

四、正式素材
按逐页稿使用指定图片，保持原比例和关键内容完整。
产品截图、人物、Logo及原始图表不得擅自改画或替换。
如当前工具无法准确使用某项素材，请说明，不要生成一张看似相近的图片冒充原素材。

五、画面质量
每张图片对应一页完整幻灯片，画幅为16:9，不生成电脑屏幕、投影幕布、透视样机或多页拼图。
文字直接呈现在图片中，使用清晰、足够大的中文，保证会议投屏时能够阅读。标题、正文、数据标签与页脚层级分明，四周保留安全边距，不出现文字截断、重叠或溢出。
不添加无关文案、随机英文、装饰性数字或额外水印。
不要用复杂纹理干扰正文，也不要以缩小字体的方式硬塞内容。

六、整套生成与交付
按照已确认的逐页稿，一次性完成全部页面，无需先生成样页或中途等待确认。
整套沿用统一的配色、字体气质、标题层级和页脚规范，根据各页内容调整构图，避免风格漂移或版式重复。
每页单独输出一张16:9高清图片，按"01_封面、02_页面标题……"依次命名，不要拼成多页长图或缩略图合集。
生成过程中逐页核对文字、数字、素材及页序，确保没有漏页、重复页或未经确认新增的内容。
全部完成后，按顺序交付所有图片；如当前环境支持文件打包，同时提供ZIP压缩包。
```

三张样张出来后，先核对风格和字号，再让它出其余页面；产出图片按页序合成 PDF。

## P5 · 图片版 PDF 还原成 PPTX —— 第 5 步，出图后的可选延伸

只在用户明确"后面还要改"时用。还原是有损的，要提前说清。

```
请使用ppt-master-skill，将我上传的整份PDF转换为16:9宽屏比例的可编辑PPTX。
先按当前Skill说明选择适合的PDF转换或图片重建流程。

一、整套转换
处理PDF中的全部页面，保持原页序、页数和内容对应关系，不要漏页、重复页或擅自合并、拆分页面。
先检查PDF是文字型、图片型还是混合型，据此选择提取与重建方式。如原页面不是16:9，不要拉伸或裁切内容，请说明适配方案。

二、还原目标
尽量保留原PDF的整体设计、构图、配色和图文位置，同时让主要文字可以在PPT中编辑。
采用混合还原方式：
- 标题、副标题、正文、标签、关键数字和页码，使用可编辑文本框。
- 简单色块、线条和基础图形，尽量使用PPT原生形状。
- 复杂照片、插画和纹理，保留为独立高清图片。
- 需要更新数据的图表，使用我提供的原始数据重建；没有原始数据时，不猜测数值，明确说明编辑限制。

优先使用上传的正式素材，避免从PDF中反复裁切、压缩图片；保持图片原比例和关键内容完整。

三、文字与背景处理
对照已确认的逐页稿核对文字和数字；如未提供逐页稿，以PDF为准，识别不清的内容列出待核对。
文字转为文本框后，必须清除背景中对应的原文字，避免出现重影，或修改后露出旧文字。不要将整页截图铺底，再覆盖文本框充当可编辑页面。
文字与复杂背景粘连时，优先使用原始素材或无字背景。确实无法干净拆分的区域，保留必要的图片形式，并在交付说明中标明，不要强行补画造成失真。
不得擅自改写内容，或改变产品外观、人物、Logo、图表含义及数据关系。

四、整套一致性与检查
统一同级标题、正文和页脚的字体、字号及位置规范，同时保留原PDF中不同页面的布局特点。不因统一格式而改变重点、遮挡内容或缩小文字硬塞。
逐页检查：
1. 文字有无错漏、重叠和溢出
2. 图片有无变形、模糊或裁切
3. 背景有无残留旧文字
4. 页序、数据、单位和来源是否准确

五、交付
直接完成整份PDF的转换，无需逐页等待确认。
如需分批处理，请自行管理页序，最后合并为一个PPTX。
交付完整PPTX及对应的整套PDF预览，并按页码列出：仍保留为图片的主要内容、无法准确识别的文字、明显还原差异和需要人工核对的事项。
无法满足的要求如实说明，不将图片元素标为可编辑。
```

## P6 · 直出可编辑 PPTX —— 第 5 步，PPTX 路线

原文自带三页样稿，与本流程的检查点一致，原样使用。调用 `ppt-master` 前先确认它的依赖能导入（见 `paths.md`），缺包就让用户装。

```
请使用ppt-master-skill，根据已经确认的素材、逐字稿、风格说明，制作可编辑PPTX。

先做三页样稿：
封面、内容最多的一页、图表或流程最复杂的一页。
如果页面类型有重合，请另选一页，覆盖不同的排版需求。
先保留原页码，方便与内容定稿核对。

可编辑要求：
1. 标题、正文、页码和关键数字使用可编辑文本框
2. 需要更新数据的图表，使用带可编辑数据的原生图表，不要用矩形、线条拼出外观后，视为已经满足要求
3. 表格使用可编辑表格，保留增删行列和修改内容的能力
4. 流程图的节点、文字和连接线分别可编辑；移动节点时，连接线应能跟随调整
5. 复杂插画和照片可以使用图片，但标题、正文和需要修改的标注应独立保留
6. 如提供了强制使用的PPT模板，请沿用原模板的母版、版式及公共元素

严格使用已经确认的内容，不新增观点、事实或数字。不要用整页图片代替可编辑页面。如果某项要求无法实现，请明确说明限制和替代方案，不要自行降低要求。
导出三页样稿的PPTX和对应预览图，说明哪些元素可编辑、哪些仍是图片，以及有无字体替换或其他需要注意的问题。
等我确认后，再继续制作全套。
```

## P7 · 单页改稿 —— 第 6 步验收不过时

只改一页，永远带页编号和截图。

```
只修改第［ ］页，以我提供的实际打开截图为依据。

问题：［实际看到的问题］。
希望改成：［具体结果］。
允许修改：［布局、字号、图片大小等范围］。
需要保留：［满意的设计、原文、数值、其他页面等］。

请先判断原因，再调整相关对象。不要为了修复局部问题，重做整页或整套风格。
修改后重新导出并检查，确认原问题是否解决，同时检查有无新增的遮挡、溢出、变形或内容遗漏。
把修正保存到制作源文件，避免下次导出又恢复旧问题。交付修改后的文件，并简要说明改了什么。
同一个问题连续两轮没有改善时，先检查原因，不要继续重复生成。
```

多页同类问题（例如全篇字号偏小）不要套这条逐页改，直接说明范围让制作技能统一调整，然后整份复检。

## 占位符对照

| 占位符 | 从哪取 |
|---|---|
| ［演示场合］［汇报场合］ | `brief.md` 的"什么场合" |
| ［目标受众］ | `brief.md` 的"给谁看"＋受众四维 |
| ［选定Skill］ | 网页路线：`frontend-slides` 或 `guizang-ppt-skill` |
| ［ ］（P7 页码） | `outline.md` 里的 P 编号 |

## 本流程另外要求的话（不是原文的 prompt，是规矩）

- 每十页一批，出完报一句"P11–P20 好了"，不逐页请示。
- 三页样稿只给真产物：能翻的 HTML、原始分辨率的 PNG、能打开的 PPTX。截图不算。
- 样稿确认时只问一句："这三页的方向对不对，哪里不对？"
