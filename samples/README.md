# 样例

七份完整样例，覆盖七种互不重叠的场合。场景按"谁在场 × 要达成什么"划分：

| # | 样例 | 谁在场 | 要达成 | 版式 | 页数 |
|---|---|---|---|---|---|
| 01 | `client-proposal/` | 外部 · 尚未合作 | 争取资源或签约 | 咨询风，白底蓝调，16:9 | 14 |
| 02 | `delivery-review/` | 外部 · 已合作 | 维护信任与续约 | 青蓝数据风，16:9 | 5 |
| 03 | `internal-briefing/` | 对内 · 一对多 | 动员与传播 | 深色大字报，橙调，16:9 | 8 |
| 04 | `decision-brief/` | 对内 · 少数人 | 当场拍板 | 深蓝配琥珀，16:9 | 5 |
| 05 | `weekly-sync/` | 对内 · 团队 | 信息对齐 | 深色极简，16:9 | 5 |
| 06 | `training/` | 对内 · 学员 | 教会做某件事 | 米色教学，4:3 | 6 |
| 07 | `self-read/` | 无人在场 | 事后能查能复核 | 文档体，衬线，16:9 | 5 |

## 这些样例证明了什么

**版式能力**：同一套内容逻辑可以落到咨询、大字报、教学、文档四种视觉语言上，画布也能在 16:9 与 4:3 之间切换。

**场景映射**：受众关系决定结构，目的决定收尾。01 与 03 用同一份行业事实，对客户是"判断 + 出处 + 不该做什么"，对同事是"三条事实 + 关我什么事 + 三个人一个场景"。

**可交付性**：七份都能双击打开、键盘翻页、断网可用；七份都过了脚本机检，并在无头浏览器里逐页翻过，无溢出、无控制台报错。

## 这些样例**没有**证明什么

**没有证明流水线已端到端自动生成。** 页面是 agent 手写的 HTML 实现，不是由 `frontend-slides`、`guizang-ppt`、`imagegen` 或 `ppt-master` 跑出来的产物。流程负责的是需求、结构、检查点和验收标准；具体排版目前仍由 agent 执行。

**没有证明 brief 与 outline 一定先于页面产生。** 只有 `client-proposal` 走了完整闸口（判档 → 问需求 → brief → 逐页稿 → 机检 → 冻结 → 三页样稿 → 全量）。其余六份是先做出页面，再按成品回溯整理出 `brief.md` 与 `outline.md`。文档与成品一致，但顺序是反的。

**没有真实用户参与。** 所有反馈都来自作者自查，没有外部使用者跑过这套流程。

## 打开方式

每个目录下的 `index.html` 双击即可，左右键翻页，`F` 全屏。没有外部依赖，断网可用。

## 数据说明

`client-proposal` 的行业数据来自 2026-11 的公开报道，原始出处写在页脚。

`delivery-review`、`weekly-sync`、`internal-briefing`、`decision-brief`、`self-read` 里的业务数字（覆盖率、人日、周期、报价）都是示例设定，不来自任何真实公司数据。
